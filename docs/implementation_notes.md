## 真实数据发现

- 地图数据版本：`4ff82651f7af3859a16ebce6197fe363ac40d9a1`。920 个 Level_Entry 中 466 个属于 Overworld；当前均有参考图、无重复入口。图像索引共 922 项，有两张参考图没有 Marker：`mirror8_v5`、`mirror_6`。
- 上游按依次覆盖的高度范围分类：Overworld [-4,10]、Sky [10,75]、Underworld [-57,-4]。边界 10 最终属于 Sky，-4 属于 Underworld。实现及测试遵循此规则。
- 参考图片和高分辨率地图瓦片实际在 `joric/ootss_tileset`。P4 用到的资源与该仓库固定 commit 核对字节，逐项 SHA256 保存在结果中。
- 上游 pHash：32×32 灰度、DCT 左上8×8、AC 中值；HSV 16×4×4。Pillow 与 Canvas 缩放并不保证一致，因此统一重算参考及视频特征，没有混用上游预计算 hash。
- 保留 pHash 排序、HSV 同距排序，增加 SIFT/RANSAC 复核前12名。候选拒绝规则是实验启发式，分数不解释成概率。局部特征只用于辅助，最后仍核对静态结构。
- 地图瓦片近似正俯视，视频存在透视和动态阴影。SIFT/RANSAC 单应变换能在三个局部区域对齐地形；将关卡入口的原始坐标反投影回视频，可检查角色是否靠近入口格。入口常为地面星形节点，不必有门框。

P4 的所有29个身份已经根 Agent 对照参考图及连续样本核对。Luna 用于两次局部图册判断；它初次把一些真实关卡当成主世界，之后由实际参考图纠正。对入口远帧有疑虑的条目补看了进入前近帧。这说明图册可有效辅助判断，但不适合让小模型仅凭风格自动给全片标签。

实际暴露的新问题是：大关卡只在最初参考视角得到好匹配，后面镜头滚动到相邻房间时检索会失效。若只用匹配命中的时间，会截短P9、P15、P22等访问；若将同主题长段当作单张棋盘匹配，也会过度解释。现在通过高清局部帧、返回起始布局、出入转场及游戏连通房间地图区分入口访问与内部子房间，在理由中限定匹配证据范围。新增recovery工具只取证，不自动合并或确认。

新增测试包括文件名清洗、同CID恢复文件路径保留、汇总只包含实际已确认访问、重复访问与阶段过滤，以及真实地形SVG内嵌和多分区高度回归。12项测试通过。浏览器核对了分P筛选、URL深链接、参考图加载、视频URL和窄窗口弹窗；修正了小窗口完整地图受最小倍率限制、长标题控件溢出，以及动画定位导致弹窗越界的问题。完整统计与限制见results/stage1/REPORT.md。
