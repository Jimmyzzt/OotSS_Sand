# 存档导入：后续方案（未实现）

目标是帮助玩家查攻略和标记完成，不重建完整世界可达性模拟器。

## 第一版建议

1. 浏览器本地读取用户选择的 Status.sokoban_status，不上传、不改写。检查版本、长度和解析边界，展示匹配数量及未匹配 ID，确认后应用。
2. 仅用明确的 SOLVED 标志标为完成。PARTIALLY_SOLVED 只显示部分完成；未出现的关卡记为未知，不能当作当前可达或尚未解锁。多阶段关、别名、多存档关单独核对，不凭相似名称合并。
3. 导入状态与手工勾选区分来源，手工覆盖优先。支持差异预览、替换／撤销某次导入、单独清除导入来源；多个游戏存档使用独立进度档案，不自动取并集。
4. 未完成入口说明为「未标记完成，可达性未判定」，不把所有未完成入口推荐为下一关。

## 避免暂不可达区域误导

第一版把完成状态和当前可达分开。默认仍是完整攻略地图，明确提示「含后续阶段区域；未完成不代表目前可进入」。可增加玩家自选进度范围（主世界初访／已到上方／已到下方／显示全部），作为浏览辅助，不宣称精准解锁；同一世界含后续回访关卡，不能只按世界或视频分 P 推断可达。

之后再支持「仅显示已探索区域」：读取 overworld.history 的探索迷雾，未知区域不显示名称、数量或标签。探索过仍不保证现在能进入，因此至少区分已完成／部分完成／已探索未完成／未探索／可达性未知。只有确切解锁条件和证据成立，才显示「尚未解锁」及原因；无把握时保留未知。

完整可达性依赖冰笼、传送门、层间通路和动态障碍，不适合第一版凭阶段猜测。建议先做完成标记，再增加探索范围，最后考虑可靠的解锁提示。

## 调研依据

[xPaw 项目](https://github.com/xPaw/order-of-the-sinking-cost) 使用本地存档，将完成、部分完成、解锁和暂不可达分开，默认按迷雾隐藏未知内容。[存档格式说明](https://github.com/xPaw/order-of-the-sinking-cost/blob/main/docs/SAVES.md) 记录 Status 的逐关标志、世界历史中的迷雾信息，并提示状态文件可能短暂滞后。这是第三方逆向结果，需实际样本验证，不是官方规范。

若复用代码或数据，先固定上游提交、核对对应文件许可并保留署名。本次仅调研，没有读取玩家存档，也未增加存档上传或自动完成接口。
